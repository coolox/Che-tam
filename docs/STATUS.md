## Что это за проект

**Hearth** — приватный видеомессенджер для узкого круга родственников
(Турция ↔ Туркменистан), кодовое имя репозитория **che-tam** (переименован
из `hearth` 22.09). Главная ценность — видеозвонки в условиях жёсткой
цензуры трафика в Туркменистане. Полная спецификация: `docs/spec.md` v2.1.

Каждый TASK-XXX выполняет ровно один агент-исполнитель ("Фатима" сегодня,
может быть другой агент завтра — не важно кто). Роль исполнителя описана в
`AGENTS.md`. Hermes — единственный, кто ставит задачи, принимает код,
собирает Android-билды (`gradlew`, `prebuild`), устанавливает на устройство
и переносит проект дальше по фазам. **Исполнитель никогда не собирает и не
запускает build/prebuild/gradle/эмулятор/устройство** — это правило
закреплено во всех task-файлах и в `AGENTS.md`.

## В одном репозитории — две независимые линии работы

Это главный источник путаницы, если не знать про него заранее.

### Линия 1: Canary (TASK-001*, TASK-RESTORE-01) — Фаза 0 разведки

Отдельное Android-приложение `net.hearth.canary`, которое **не является
частью мессенджера**. Его единственная цель — собрать реальные данные о
доступности нашего VPS из Туркменистана, прежде чем проектировать пути
звонков (раздел 4 спеки). Логика: HTTPS/WS проверки каждые ~15 минут,
локальный журнал, экспорт JSON вручную через share sheet.

### Линия 2: UI Preview (UI-001…UI-007) — витрина интерфейса, без сети

Отдельный демо-интерфейс мессенджера на демо-данных: список чатов, пузыри,
экраны звонка, настройки. **Нет сервера, нет сети, нет реальной камеры/
микрофона, нет авторизации.** Цель — дать посмотреть в Турции, как будет
выглядеть финальное приложение, до того как строится backend.

**Обе линии живут в одном App.tsx одного репозитория.** Canary был написан
первым (коммит `867da3a`), затем UI Preview начал итеративно переписывать
`App.tsx` под демо-мессенджер (с `78c5c3a`). Из-за этого текущий `App.tsx`
показывает UI Preview, а не экран канарейки — это ожидаемо, не баг.

**Если сборка Canary снова понадобится:** актуальный код канарейки живёт в
`src/nativeMonitor.ts`, `src/storage.ts`, `src/exportJournal.ts`,
`src/schedulePolicy.ts`, `src/types.ts` и Android-нативном слое
(`android/.../ForegroundMonitorService.kt`, `WorkManagerScheduler`). Эти
файлы не удалялись при переходе на UI Preview. `App.tsx` пришлось бы
переключить обратно на canary-экран (или собрать из отдельного git-referenc
на коммит `867da3a`) — см. раздел "Текущая граница работы" ниже.

## Место проекта в общей спеке (раздел 10, порядок фаз)

Мы всё ещё внутри **Фазы 0** (разведка/канарейка). TASK-002 (прямое
соединение внутри Туркменистана), TASK-003 (тестовый международный
видеозвонок) и далее по спеке — **не начаты**. UI Preview технически
забегает вперёд по интерфейсу Фазы 1+, но работает на демо-данных и не
трогает architecture/backend, поэтому не нарушает порядок фаз, только
параллелит визуальную часть.

## Что дальше делает исполнитель (когда Hermes поставит задачу)

Ждать конкретный TASK-XXX от Hermes с явным путём:
1. Либо продолжение Canary (проверить/доделать TASK-RESTORE-01).
2. Либо продолжение UI Preview (UI-006/UI-007).

Не начинать TASK-002 и далее по спеке, пока TASK-001 не принят Hermes.
Не собирать/не запускать build самостоятельно — только Hermes.
