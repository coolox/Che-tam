# ADR-004 — сквозное шифрование и сервер-«слепой почтальон»

**Статус:** Принято (решение Арслана, 2026-10-07)
**Заменяет в spec.md:** цель 1.1.6, не-цель «E2E позже» (1.2), Supabase в 5.1/5.2, поля `body`/`search_vector`/`encryption_version = 0` в 6, TASK-060 и TASK-061 в фазе 12.
**Связано:** ADR-001 (доставка через push), ADR-002 (сервер и домены), ADR-003 (вход по приглашению, одно устройство).

## Коротко для любого агента

1. Сервер **никогда** не видит текст, фото, голосовые и видео. Только зашифрованные конверты.
2. Шифрует и расшифровывает **только телефон**. Ключи не покидают телефон.
3. Сервер хранит конверт, **пока получатель его не забрал**, затем удаляет.
4. Вся история переписки живёт **только на телефонах** участников.
5. Потеря истории при смене телефона закрывается **автоматической зашифрованной резервной копией**.
6. Криптографию **не пишем сами**. Только проверенная библиотека (libsodium).

Если задача требует отправить на сервер что-то в открытом виде — это противоречие этому ADR: стоп и вопрос Арслану.

## Контекст

Чё-Там — закрытый мессенджер для 15–20 человек, часть из них в Туркменистане. Для Арслана приватность переписки — обязательное требование: её не должен читать никто, кроме участников, включая хостинг, владельца сервера и любого, кто получит доступ к серверу.

Исходная spec откладывала E2E «на потом» и хранила сообщения на сервере бессрочно. Встраивать шифрование в готовую систему намного сложнее, чем заложить с начала. Серверная фаза ещё не начата (gate ADR-002 перед APP-007), поэтому решение принимается сейчас.

Полностью без сервера (телефон–телефон) не работает: мобильные сети за NAT, блокировки в Туркменистане, телефоны не онлайн одновременно, спящий телефон нельзя разбудить без push. Поэтому сервер нужен, но только как почтальон.

Условие, которое упрощает задачу: по ADR-003 у каждого человека ровно **одно устройство**. Синхронизации ключей между устройствами нет.

## Решение

### 1. Ключи устройства

- При первом входе по коду приглашения телефон создаёт две пары ключей: **X25519** (шифрование) и **Ed25519** (подпись).
- Приватные ключи — только в `expo-secure-store` (Android Keystore). Никогда не в SQLite в открытом виде, не в логах, не на сервере.
- Публичные ключи отправляются на сервер при регистрации и привязываются к аккаунту.
- **Отпечаток ключа** («код безопасности», 60 цифр группами) виден в карточке собеседника. Двое могут сверить его при встрече или голосом.
- Ключ собеседника сменился (новый телефон) → в чате системная строка «У {имя} новый телефон. Код безопасности изменился». Отправка не блокируется.

### 2. Шифрование сообщения (версия 1)

Библиотека: **libsodium** через React Native-обёртку. Конкретный пакет выбирается в задаче CRYPTO-001.

- Для каждого сообщения — случайный ключ сообщения (32 байта).
- Содержимое (JSON: тип, текст, reply-ссылка, метаданные вложений) шифруется **XChaCha20-Poly1305** этим ключом.
- Ключ сообщения шифруется отдельно для каждого устройства-получателя через `crypto_box_seal` его публичным X25519-ключом.
- Отправитель подписывает конверт **Ed25519**. Получатель проверяет подпись до расшифровки; неверная подпись — сообщение отбрасывается и пишется в журнал без содержимого.
- **Группы** (до 20 человек): то же самое, ключ сообщения шифруется для каждого участника. Своего группового протокола нет.
- В конверте всегда есть `encryption_version = 1`. Версия `0` (без шифрования) на сервере **запрещена** и отклоняется.

**Известное ограничение v1:** нет forward secrecy (как в протоколе Signal). Если украдут телефон вместе с ключами, можно расшифровать перехваченные ранее конверты. Это принято сознательно ради простоты. Переход на Double Ratchet — возможная версия 2, отдельным ADR.

### 3. Сервер — «слепой почтальон»

Сервер хранит только:

| Что | Зачем |
|---|---|
| аккаунты, публичные ключи, приглашения | вход и шифрование |
| состав чатов (кто в каком чате) | кому доставлять |
| **конверты**: id, chat_id, sender_id, адресат, шифротекст, подпись, `encryption_version`, created_at | доставка |
| отметки «получено устройством» | удаление и галочки |
| зашифрованные резервные копии (п. 6) | восстановление |

Правила:
- Конверт удаляется для получателя сразу после подтверждения получения (ack). Когда забрали все — удаляется полностью.
- Незабранный конверт живёт **30 дней**, потом удаляется. Отправитель видит «Не доставлено».
- На сервере **нет** текста, полнотекстового поиска (`search_vector` удаляется из модели), превью и миниатюр.
- **Push (FCM)** несёт только сигнал «есть новое» и id конверта. Текст уведомления телефон показывает после расшифровки у себя.
- Логи сервера: без содержимого конвертов, ключей, кодов приглашения и токенов.
- Сервер видит **метаданные**: кто, кому, когда, размер. Это известное ограничение, принимается.

**Бэкенд: Node.js + PostgreSQL** на своём VPS, а не Supabase. Серверу-почтальону хватает небольшого API и одной базы. Это проще переносить на новый адрес при блокировке. Регион VPS и боевой IP решаются в ADR-002.

### 4. Вложения (фото, видео, голосовые, файлы)

- **v1:** телефон шифрует файл целиком случайным ключом через `crypto_aead_xchacha20poly1305_ietf` и загружает на сервер только шифротекст.
- Потоковое шифрование больших видео — отдельное решение после v1; замену `secretstream` самостоятельно не изобретать.
- Ключ файла и его хеш передаются внутри зашифрованного сообщения.
- Сервер удаляет файл, когда его скачали все получатели, или через 30 дней.
- Миниатюры делает телефон-получатель после расшифровки.

### 5. История — только на телефонах

- Переписка хранится в локальном SQLite (как сейчас), включая расшифрованные сообщения и вложения.
- Поиск — только локальный (уже сделан в 0.6.7).
- «Удалить у себя» — локально. «Удалить у всех» — позже, как зашифрованное служебное сообщение.
- Статусы «доставлено» — по ack сервера; «прочитано» — зашифрованное служебное сообщение.
- Шифрование самой локальной базы (SQLCipher) — следующий шаг, не блокирует v1.

### 6. Резервные копии

Без них смена или потеря телефона = потеря истории. Поэтому копии **автоматические**, человек ничего не делает руками.

- При первой настройке человек задаёт **пароль резервной копии** (минимум 8 символов). Приложение предупреждает: «Без этого пароля переписку восстановить нельзя. Даже Арслан не сможет».
- Ключ копии получается из пароля через **Argon2id** (`crypto_pwhash`). Пароль на сервер не отправляется.
- Раз в сутки (при Wi-Fi и зарядке, если возможно) телефон шифрует свою базу и вложения и загружает на сервер **одну последнюю копию**, заменяя предыдущую.
- Сервер хранит копию, но расшифровать её не может.
- **Новый телефон** (ADR-003): Арслан выдаёт новый код приглашения → новые ключи устройства → «Восстановить переписку?» → пароль → история на месте.
- Пароль забыт → история не восстанавливается, новые сообщения приходят. Восстановления пароля нет — это цена приватности.
- Для пожилых родственников Арслан помогает задать пароль при установке. Хранить пароль у Арслана можно только с согласия человека и вне приложения.

## Последствия

**Плюсы:** переписку не читает никто, кроме участников; утечка или изъятие сервера раскрывает только метаданные; сервер простой, дешёвый и легко переезжает.

**Минусы:** потеря телефона без пароля копии = потеря истории; нет forward secrecy в v1; сервер видит метаданные; больше работы в приложении (ключи, шифрование, копии).

## Задачи (новые, в серверную фазу, до или вместе с APP-007)

- **CRYPTO-001 — проверка библиотеки.** Выбрать RN-обёртку libsodium, совместимую с текущими Expo/React Native, arm64 и New Architecture. Доказать на устройстве/эмуляторе: X25519, Ed25519, XChaCha20-Poly1305, `crypto_box_seal`, `crypto_pwhash` и шифрование файла 5 МБ через `crypto_aead_xchacha20poly1305_ietf`. Тесты на эталонных векторах. Без этого остальное не начинать.
- **CRYPTO-002 — ключи устройства.** Генерация при входе, `expo-secure-store`, публичные ключи на сервер, отпечаток в карточке собеседника, событие «ключ изменился».
- **CRYPTO-003 — конверт.** Шифрование/расшифровка/подпись сообщения, fan-out для групп, отклонение `encryption_version = 0`. Интеграция с outbox (`client_message_id` остаётся снаружи конверта для идемпотентности).
- **CRYPTO-004 — вложения.** v1: шифровать файл целиком через `crypto_aead_xchacha20poly1305_ietf`, передавать ключ внутри сообщения и проверять хеш. Потоковое шифрование больших видео — отдельное решение после v1.
- **CRYPTO-005 — резервные копии.** Пароль, Argon2id, ежедневная копия, восстановление на новом телефоне.

## Правила для агентов

- Не изобретать криптографию: только функции libsodium, без своих схем, без `Math.random` для ключей.
- Никогда не логировать текст сообщений, ключи, пароли, коды приглашения — даже в debug.
- Fake transport в localtest может работать с открытым текстом только локально; реальный транспорт принимает только конверты `encryption_version = 1`.
- Любое отступление от этого ADR — только после явного решения Арслана.
