# ADR-002 — сервер и домены для «Чё-Там» (черновик, без решения)

- **Статус:** draft — требует отдельного письменного утверждения Арсланом.
- **Дата:** 2026-10-04
- **Область:** планирование инфраструктуры для APP-007+; этот документ не разрешает создание/изменение сервера, DNS, TLS, доменов, секретов или production-транспорта.

## Контекст

До APP-007 приложение содержит только локальные, тестируемые контракты: transport policy (APP-005) и auth/session boundary (APP-006). Production endpoint, сетевой adapter, Node.js + PostgreSQL, URL, ключи и секреты намеренно отсутствуют.

Нужны отдельные решения о VPS/регионе, TLS, доменах, резервных точках входа и механизме обновления endpoint list. По ADR-004 backend уже выбран: Node.js + PostgreSQL, сервер-«слепой почтальон». В условиях Туркменистана нельзя считать FCM, UDP или единственный адрес гарантированно доступными; одновременно нельзя добавлять скрытые обходы, неутверждённые туннели или постоянные соединения без принятой политики.

## Предлагаемое решение для утверждения

1. **Backend:** Node.js + PostgreSQL, сервер-«слепой почтальон» по ADR-004, на выбранном отдельным решением VPS. До подтверждения VPS, региона, схемы бэкапа и модели обновлений ничего не разворачивается.
2. **TLS и порт:** Caddy на TCP/443 с управляемыми сертификатами. На корневом домене — безобидный статический сайт; API и прочие сервисы не должны непреднамеренно раскрывать семейное назначение системы.
3. **Разделение ролей:** сервер тихих сообщений и relay-инфраструктура должны быть разнесены по ролям, хостам и наблюдению. Это не разрешает реализацию звонков или relay до отдельной задачи и приёмки.
4. **Домены:** основная точка входа и тихая резервная точка должны находиться на разных доменах. Предусмотреть 2–3 резервных домена, но зарегистрировать, настроить DNS или публиковать адреса только после письменного согласования списка.
5. **Endpoint list:** APP-005 уже задаёт локальную policy с opaque ID. Для production требуется утверждённый, подписанный/аутентифицированный источник versioned endpoint list, правила ротации, срок действия, rollback и аудит изменений. До этого нельзя подключать реальный adapter.
6. **Доставка Android:** следовать принятому ADR-001: основной путь — FCM без постоянного соединения. Fallback с постоянным соединением включается и клиентом, когда sync находит сообщения, пришедшие без push; серверный флаг — дополнительный сигнал. iPhone отложен.
7. **Наблюдаемость и данные:** заранее определить минимальные журналы, срок хранения, резервное копирование, доступы и процедуру аварийного отката. В логи не попадают пароли, invite-коды, токены и содержимое сообщений.

## Открытые вопросы

- VPS и регион: ждём результаты Canary из Туркменистана.

- Production: нужен отдельный новый IP; существующие адреса не считаются утверждёнными для production.

## Альтернативы

- **Один домен/одна точка входа:** проще, но создаёт единую точку отказа и не соответствует требованию резервирования.
- **Managed SaaS вместо self-hosted Supabase:** быстрее старт, но требует отдельной оценки юрисдикции, данных, расходов и доступа; не принят этой ADR.
- **Прямое добавление production URL в клиент:** отклонено. Endpoint selection должна оставаться за versioned list и утверждённым источником.
- **Постоянный WebSocket как нормальный режим:** отклонено ADR-001; допустим только как оговорённый fallback.

## Последствия и обязательный gate

До одобрения этой ADR запрещены:

- APP-007 и любые последующие задачи, которым нужен production backend/domain/adapter;
- создание или изменение VPS, DNS, Caddy/nginx, TLS, firewall, Supabase, базы, relay или секретов;
- добавление endpoint URL/адресов, ключей, реальных auth/transport adapters;
- выпуск APK, заявляющего поддержку реального аккаунта или production connectivity.

После одобрения документ должен быть обновлён конкретными, проверяемыми решениями: владельцы доменов, список доменов и ролей, VPS/регион, порты, TLS-процедура, backup/restore RPO/RTO, source/format/signing endpoint list, правила ротации и rollback, перечень секретов и способ их хранения. Следующей задачей становится отдельный, ограниченный APP-007 task-file.

## Статус выполнения

Этот документ — только черновик архитектурного решения. Никакая инфраструктура не создана и не менялась.
