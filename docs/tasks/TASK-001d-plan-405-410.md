# TASK-001d — план выпусков 4.0.5 и 4.1.0

> Принят по сообщению Арслана. Этот документ фиксирует полный план и заменяет ранее сформулированные промежуточные планы. `fcm_push` отложен до предоставления файлов Firebase.

## Общие правила

- Код пишет только Фатима. Гермес готовит задачи, проверяет, собирает, коммитит и выкладывает.
- Каждый пункт — отдельный заход Фатимы и отдельный коммит в `origin/codex/task-001d-canary-v4`.
- Пункт считается завершённым только при наличии хеша коммита в origin. Передача задачи Фатиме не является завершением.
- При падении сборки или теста ошибка передаётся Фатиме; Гермес не правит код самостоятельно.
- Отчёт после каждого пункта: `номер — хеш в origin — результат тестов`.
- Не коммитить `secrets.properties`, `.env*`, keystore, `local.properties` или иные секреты.

## Версия 4.0.5 — быстрая, для Туркменистана

### 1. Приёмка

TASK-001d-2 принят: 12,5 часа, примерно 96% прогонов, сервер 100%. Записать приёмку в `PROGRESS.md`.

### 2. Правки лёгкого прогона — TASK-001d-2I

2.1. Контроли: GET вместо HEAD, только HTTP/1.1; любой HTTP-ответ после TLS — успех, статус сохраняется в `httpStatus` (403 — успех).

2.2. Проверки нашего сервера: новое соединение каждый раз, без пула, чтобы всегда измерялись `dnsMs`, `tcpMs`, `tlsMs`.

2.3. `networkType` не должен быть `null`.

2.4. `bytesTx`/`bytesRx`: суммарно на прогон в `run_summary`; по отдельным тестам — только если больше нуля.

2.5. Найти и исправить причину пустого `wifiRssi`, когда телефон долго в покое.

2.6. Журнал отбрасывает записи с пустым `timestampUtc`.

2.7. В `cycle_start` добавить `screenOn`, `deviceIdleMode`, `powerSaveMode`, `appStandbyBucket`.

2.8. `ws_closed_event`: в `onClosed`/`onFailure` постоянного WebSocket сразу писать запись с `connectionId`, `ageSec`, `closeCode`, `exceptionClass`, `networkType`, `screenOn`, `detectedBy` (`callback` или `probe`).

### 3. Связка логов и закрытия на сервере — TASK-001d-2J

3.1. Клиент посылает `X-Canary-Device-Label` и `X-Canary-Connection-Id` при WS upgrade и во всех HTTP-проверках.

3.2. Сервер пишет label и клиентский id в `canary_http_request`, `canary_ws_open`, `canary_ws_close`.

3.3. Каждое закрытие WS (клиент, обрыв TCP, nginx timeout) записывается ровно один раз: длительность, код, причина, время последнего кадра.

3.4. Заголовки необязательны: legacy 4.0.4 без них продолжает работать, а в логе `null`. Нужен тест: HTTP без заголовков → 200; WS без заголовков принимается.

3.5. Не добавлять server-side ping.

3.6. Выкладка: параллельный запуск на временном порту → проверка → переключение; если служба не работает — откат.

### 4. Сборка 4.0.5

Прогнать тесты, `assembleRelease`, `apksigner verify`, вычислить SHA-256, скопировать APK в `/root/backups/apk/`, отправить APK Арслану в Telegram.

## Версия 4.1.0 — после 4.0.5

### 5. TASK-001d-3 — TASK-001d-2K

5.1. Полный прогон раз в час: `ws_domain`, `ip_direct` (2 SNI × HTTP/WS), `doh_resolve` (3 провайдера), `latency_sample`, `dns_consistency`.

5.2. TURN-клиент: `turn_tls` (5349) и `turn_tcp` (3478), временные учётные данные от `/hearth-canary/turn-cred`, эхо 8 КиБ.

5.3. `payload_upload`: 20/120/500 КиБ раз в 6 часов, 2 МиБ раз в сутки.

5.4. Бюджет: суточный счётчик; после 10 МиБ на наш сервер — только лёгкие прогоны и запись `budget_paused`.

5.5. Ночная выгрузка журнала на `/hearth-canary/journal` с подтверждением сервера.

### 6. Новые проверки полного прогона — TASK-001d-2L

6.1. `ws_heartbeat`: три постоянных WebSocket с ping раз в 60, 240, 540 секунд; каждая смерть создаёт `ws_heartbeat_dead` с `intervalSec`, `ageSec`, причиной, `screenOn`, `deviceIdleMode`.

6.2. `fcm_reach`: TCP+TLS до `mtalk.google.com:5228`, `mtalk.google.com:443`, `fcm.googleapis.com:443`, `firebaseinstallations.googleapis.com:443`, `android.clients.google.com:443`; в `cycle_start` добавить `gmsAvailable`.

6.3. `imo_reach`: TLS до `imo.im:443`, отдельный `testType`.

`fcm_push` отложен до получения файлов Firebase от Арслана.

### 7. Сборка 4.1.0

Как в пункте 4: тесты, `assembleRelease`, `apksigner verify`, SHA-256, копия в `/root/backups/apk/`, APK Арслану в Telegram. В итоговом отчёте перечислить хеши всех коммитов пунктов 1–7.
