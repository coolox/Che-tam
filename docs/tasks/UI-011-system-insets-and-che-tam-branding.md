# Task: системные отступы экрана и переименование UI Preview в «Чё-Там»

- **ID:** `UI-011`
- **Status:** `approved for implementation — manual APK testing`
- **Priority:** high
- **Source:** ручное тестирование APK Арсланом
- **Depends on:** текущий UI Preview; при изменении экрана чата учесть `UI-009`

## Часть A — шапка налезает на статус-бар

### Баг

В APK заголовок/логотип верхней шапки рисуется под системной строкой Android
(время, сеть, батарея) и частично перекрывается ей. На устройствах с вырезом,
разной высотой status bar или edge-to-edge это будет выглядеть по-разному и
может стать ещё хуже.

Также требуется проверить низ экрана: нижняя навигация не должна попадать под
полосу жестов или системную навигационную панель.

### Целевой результат

- Верхняя шапка начинается **ниже системного status bar**; между системными
  иконками и содержимым шапки есть визуально достаточный зазор (ориентир
  8–16 dp *после* системного inset).
- Логотип/название и действия в шапке не перекрываются вырезом, камерой,
  временем, сетью или батареей на разных Android-устройствах.
- Нижняя навигация и интерактивные элементы у нижнего края находятся выше
  navigation bar / gesture inset.
- Контент списка и чата не получает двойных отступов и не прыгает при смене
  системной навигации.

### Требования к реализации

Проект — **React Native + Expo**, не Android Compose/XML. Поэтому не переносить
в код примеры Compose (`windowInsetsPadding`) или XML (`fitsSystemWindows`).

- Использовать корректную для текущего Expo/RN-стека работу с safe area /
  window insets: предпочтительно `react-native-safe-area-context` с
  `SafeAreaProvider`, `useSafeAreaInsets()` или `SafeAreaView`, если пакет
  уже доступен транзитивно/может быть добавлен совместимо с Expo SDK 57.
- Учитывать реальные динамические insets (`top`, `bottom`), а не хардкодить
  высоту status/navigation bar.
- Дополнительный визуальный верхний spacing 8–16 dp применять **поверх**
  `top` inset на контейнере шапки, не в обход insets.
- При edge-to-edge конфигурации Expo/Android проверить, какая часть UI должна
  получить inset: шапка, нижняя навигация и composer чата. Не дублировать
  inset одновременно на родителе и дочернем контейнере.
- Совместить решение с `UI-009`: при открытой клавиатуре composer должен
  оставаться над клавиатурой, не получая конфликтующий нижний inset.

## Часть B — бренд «Чё-Там» вместо «Hearth»

### Требование

Переименовать пользовательский бренд UI Preview с **«Hearth»** на **«Чё-Там»**.
Технические идентификаторы (package `net.hearth.canary`, slug и пути исходников)
на этом этапе **не менять**, если это не является обязательным условием
безопасной сборки: задача про отображаемое имя и визуальный бренд, не про
миграцию приложения/подписи/идентификатора Android.

### Обязательные места проверки и обновления

- текстовый логотип/название в шапке UI Preview;
- Expo display name в `app.json`: сейчас `Hearth Canary` — заменить на
  отображаемое имя **«Чё-Там»**, чтобы под иконкой лаунчера показывалось новое
  имя после новой сборки;
- splash screen / launch screen — если в текущем Expo-конфиге или проекте есть
  брендированный текст/asset;
- экран настроек, «О приложении» и прочие user-visible упоминания старого
  названия;
- launcher icon (`assets/icon.png` или фактически используемый asset): заменить
  на согласованную иконку «Чё-Там» **только когда Арслан предоставит готовый
  логотип/иконку либо отдельно утвердит дизайн**. Не генерировать и не
  выдумывать новый логотип самостоятельно.

### Важное уточнение по текущему репозиторию

На момент постановки задачи конфиг содержит `name: "Hearth Canary"`, Android
package `net.hearth.canary`, иконку `./assets/icon.png`. В исходных `.tsx`
прямого текстового упоминания `Hearth` поиском не найдено. Перед реализацией
повторить поиск по *исходникам и конфигурации*, исключив `node_modules`,
`android/build` и готовые APK.

## Allowed scope для Фатимы

Окончательно определить после чтения текущей структуры. Ожидаемо:

- `App.tsx` и актуальные UI-компоненты верхней шапки / нижней навигации;
- `app.json` (только отображаемое имя и связанная безопасная Expo-конфигурация);
- `package.json` и lockfile, только если для `react-native-safe-area-context`
  действительно требуется совместимая прямая зависимость;
- `assets/` — только после отдельного предоставления/утверждения новой иконки;
- focused tests, если текущая инфраструктура покрывает layout/config.

## Не трогать

- Canary: `src/nativeMonitor.ts`, `src/storage.ts`, `src/exportJournal.ts`,
  `src/schedulePolicy.ts`, `src/types.ts`, Android native Canary-слой;
- Android package/applicationId, slug, signing, versionCode и существующий
  технический идентификатор без отдельной задачи миграции;
- сервер, сеть, авторизацию, звонки;
- `.env`, ключи, сессии, секреты;
- готовые артефакты `android/build/`, APK и `node_modules`.

## Acceptance criteria

- [ ] На Android шапка не перекрывается status bar, в том числе с gesture
  navigation/вырезом экрана.
- [ ] Используются реальные safe-area/window insets; нет хардкода высоты
  status/navigation bar.
- [ ] Между верхним системным inset и содержимым шапки есть дополнительный
  визуальный зазор 8–16 dp.
- [ ] Нижняя навигация учитывает нижний системный inset и остаётся полностью
  доступной над полосой жестов.
- [ ] Визуальные отступы не дублируются, чат и `UI-009` keyboard behavior не
  ломаются.
- [ ] Под иконкой после новой APK отображается «Чё-Там».
- [ ] Все существующие user-visible тексты старого бренда заменены на «Чё-Там».
- [ ] Иконка лаунчера заменяется только после утверждённого исходного дизайна;
  до этого текущая иконка остаётся без самодеятельности.
- [ ] `npm run lint`, `npm test`, `npx tsc --noEmit` проходят.

## Manual APK test checklist (Hermes / Арслан)

1. Открыть APK на устройстве с жестовой навигацией, затем при возможности с
   кнопочной навигацией.
2. Проверить шапку на главном экране, в чате, настройках и звонке: системные
   иконки не накладываются на UI.
3. Проверить нижнюю навигацию: над полосой жестов есть нормальная зона нажатия,
   ничего не обрезано.
4. Открыть чат и клавиатуру: убедиться, что совместно с UI-009 нет двойного
   нижнего отступа и composer остаётся видимым.
5. Пересобрать APK отдельным шагом Hermes и проверить название «Чё-Там» под
   иконкой, в шапке, настройках/«О приложении» и на splash screen, если он есть.

## Constraints

- Арслан в прямом сообщении явно одобрил реализацию всего пакета `UI-008`..
  `UI-012`; задача разрешена к реализации Фатимой в рамках утверждённого
  scope.
- Фатима перед изменениями делает timestamped `.bak` копии изменяемых файлов.
- Фатима не запускает `expo prebuild`, Gradle, native build, эмулятор или
  устройство. APK затем собирает и проверяет Hermes.
- Если подход к insets требует изменения нативной Expo-конфигурации или
  нативного слоя, описать это точно и остановиться до build-шага; не выполнять
  нативную сборку.
