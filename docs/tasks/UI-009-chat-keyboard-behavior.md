# Task: корректное поведение клавиатуры в переписке

- **ID:** `UI-009`
- **Status:** `approved for implementation — manual APK testing after Hermes build`
- **Priority:** high
- **Source:** ручное тестирование APK Арсланом
- **Depends on:** текущий UI Preview из `UI-005v` и последующие UI-задачи, если они меняют экран переписки

## Баг

На Android при открытой переписке нажатие на поле ввода открывает экранную
клавиатуру поверх чата: она перекрывает примерно половину переписки. Поле
ввода и содержимое чата не поднимаются вместе с клавиатурой, поэтому
пользователь теряет видимый контекст разговора.

## Целевой результат

При фокусе поля ввода клавиатура должна **изменять доступную высоту чата**,
а не накладываться поверх него:

- поле ввода всегда остаётся полностью видимым непосредственно над клавиатурой;
- последние сообщения и текущая позиция переписки сдвигаются вверх;
- список сообщений корректно получает нижний inset и не оказывается скрыт под
  клавиатурой;
- при скрытии клавиатуры чат возвращается в обычное положение без рывков,
  наложений или лишнего пустого пространства.

## Требование по реализации

Использовать специализированную библиотеку **`react-native-keyboard-controller`**
(а не ограничиваться ручными расчётами высоты, фиксированными `paddingBottom`
или только `KeyboardAvoidingView`). Библиотека должна управлять keyboard insets /
анимацией для экрана чата и composer.

Перед реализацией проверить совместимость её актуальной версии с текущими
версиями Expo/React Native в `package.json`. Если для Expo нужен plugin,
настройка нативного слоя или dev build — описать это отдельным подпунктом в
задаче и не выполнять сборку: `expo prebuild`, Gradle и APK собирает только
Hermes после код-ревью.

## Discovered native limitation

`react-native-keyboard-controller` и `react-native-reanimated` добавлены в JS /
конфигурацию, но их native-модули реально станут доступны на Android только
после нового dev/production Android build. Автолинковка native-модулей и
проверка, что они попали в APK, — отдельный шаг Hermes при сборке и ручной
проверке. Фатима этот build не выполняет и не запускает `expo prebuild`,
Gradle, APK, эмулятор или устройство.

## Acceptance criteria

- [ ] На Android при тапе по полю ввода клавиатура не перекрывает composer.
- [ ] Последние сообщения остаются видимыми над клавиатурой; чат корректно
  сдвигается/скроллится к актуальному сообщению.
- [ ] После закрытия клавиатуры нет остаточного отступа, прыжка или перекрытия.
- [ ] Решение основано на `react-native-keyboard-controller` и не использует
  хрупкие фиксированные значения высоты клавиатуры.
- [ ] Не нарушены текущие жесты/скролл переписки и нижняя навигация.
- [ ] `npm run lint`, `npm test`, `npx tsc --noEmit` проходят.
- [ ] Hermes отдельно собирает и устанавливает APK для ручной проверки; Фатима
  не запускает `expo prebuild`, Gradle, native build, эмулятор или устройство.

## Manual APK test checklist (Hermes / Арслан)

1. Открыть длинную переписку и прокрутить к последним сообщениям.
2. Тапнуть в поле «Сообщение».
3. Убедиться, что поле ввода полностью находится над клавиатурой, а последние
   сообщения остаются видимыми.
4. Ввести несколько строк, закрыть и снова открыть клавиатуру.
5. Проверить отсутствие рывка, наложения и пустого зазора после скрытия
   клавиатуры.
6. Повторить на обычной и тёмной теме, когда UI-008 будет принят.
